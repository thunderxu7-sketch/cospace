# 五分钟演示

## 准备

按 README 启动，打开普通浏览器与无痕窗口，分别使用林知夏和陈屿。两人必须处于不同 Cookie 会话；观察者用于验证只读权限。模型初次加载需要等待，具体耗时取决于本机硬件。

## 演示顺序

1. **讨论与消息可靠性**：发送一句明确的发布决定，另一窗口即时收到；回复其中一条消息。可以用开发者工具临时阻断消息请求，观察失败状态和去重重试。
2. **实时文档**：两个身份打开同一文档，在不同位置编辑，展示另一位成员的光标。断开一个浏览器的网络，在两边继续编辑，再恢复网络，观察内容合并。
3. **AI 内嵌工作流**：在讨论页点击“整理讨论”，观察真实流式内容和来源。确认前文档不变，确认后才追加；展示撤销。随后从文档提取行动项，预览负责人后确认。
4. **任务与日历**：在任务表修改状态和日期，切到日历安排同一任务，再拖动时段。展示截止日期没有被安排时段覆盖；同时编辑旧版本会给出冲突提示。
5. **预算与性能**：打开预算，查看公式计算与显式保存。运行万行回归测试，展示数据库行数与实际 DOM 行数的差别；最后切换手机尺寸和只读身份。

## 简历可用表述

**CoSpace｜AI 协作工作台｜独立项目**

- 使用 React、Next.js、TypeScript 构建讨论、文档、任务、日历和预算统一工作区；以 Tiptap/Yjs 实现多人富文本编辑、光标与离线重连合并。
- 将本地模型的流式纪要、任务提取、改写与排期融入工作流，设计来源快照、修改预览、确认、幂等应用和版本保护撤销。
- 通过 WebSocket、请求去重和 PostgreSQL 乐观并发控制处理消息重试与协作冲突；采用虚拟滚动验证 10,000 条任务下的有限 DOM 渲染。

使用时保留“独立项目”身份。测试数字引用验证文档；不要将本机单次测量写成线上 SLA、用户规模或商业效果。

## 可以深入讨论的取舍

- 为什么文档用 CRDT，任务用版本比较，预算先用快照保存？
- 网络断开时哪些操作仍可继续？页面彻底关闭后离线能否重新打开？
- 模型输出不完整或内容已过期时，如何防止错误应用？
- 文档修改与 PostgreSQL 运行状态不是同一个事务，为什么仍能防止重复追加？
- 为什么撤销不能无条件回滚整份文档？
- 单进程作品集如何演进到多工作区、横向扩展与正式身份体系？
