三个浏览器引擎为 Chromium、Firefox、WebKit。UI 场景包括：聊天跨身份同步与失败重试；协作文档双人合并、离线恢复和刷新；任务创建、状态更新、日历排期和拖动；预算公式与保存；聊天和文档的 WCAG A/AA 自动检查；390px 视口与只读身份；AI 操作预览、确认和撤销；搜索弹窗焦点循环与 Escape 关闭。

Firefox 不支持 Playwright 的 `isMobile` 模拟开关，因此该引擎使用 390×844 的窄视口检查响应式布局；Chromium 和 WebKit 同时使用移动端模拟。这些检查不等同于真机、所有辅助技术或完整 WCAG 认证。

接口检查覆盖未登录/观察者写权限、Origin 校验、消息与任务创建去重、并发版本冲突、AI 应用幂等性、撤销保护、文档过期建议、排期批量回滚、预算快照版本冲突。

## 万行数据

测试向本项目 PostgreSQL 写入 10,000 条带唯一测试标记的任务，在真实任务页面执行筛选，最后清理这些行。

- 10,000 条测试任务加演示数据时，实际挂载约 **20 行 DOM**，断言上限为 50。
- 一次开发模式测量：从导航开始到任务行可见约 **835 ms**。
- 一次生产模式测量：相同流程约 **441 ms**。
- 验证中文负责人筛选、唯一任务检索及虚拟行数。

这是单机、单次、热服务的说明性记录，没有模拟高并发、慢网或低端移动设备。它证明渲染节点有界，不等于每次操作都具有同样延迟。

## 真实 AI

通过本机 Ollama 的 `qwen3:14b`，不是固定回复或伪造流式打字。

首次已记录的纪要测试：首个内容片段约 **12.2 秒**，完整建议约 **18.6 秒**，64 个增量事件、92 字符。随后验证了确认前文档不变、重复确认不重复追加、撤销恢复原文。

行动项提取、段落改写、发布排期均完成了真实生成 → 结构校验 → 应用 → 再次应用 → 撤销；还验证了取消会持久化为 `cancelled`。示例耗时分别约 19.1、2.0、28.2 秒，受模型预热、上下文和本机负载影响，不作为性能保证。

浏览器中另一次真实纪要已手动预览并确认写入发布文档，保留为演示数据。界面截图：[工作区预览](screenshots/workspace.jpg)。

## 复现

```bash
npm run db:up
npm run check
npm start
# 另一个终端：
npm run test:e2e
npm run test:ai
npm run format:check
npm audit
```

若没有已运行服务，Playwright 会自动启动开发服务；上述 33 项完整回归是在 `npm start` 的生产服务上执行的。测试会临时改变演示空间，请勿与需要保存的人工操作同时运行。

## 已知边界

- 固定的本地演示身份和单工作区，没有正式 SSO、工作区邀请或多租户隔离。
- 服务使用单进程，尚未验证分布式运行、进程硬崩溃与数据库不可用时的全部组合。
- CRDT 自动持久化有短暂防抖窗口；已有浏览器缓存可以重连补回，不应视为跨设备实时备份 SLA。
- AI 依赖模型可用性，生成内容仍需核对；排期建议可能因版本变化或冲突被拒绝。
- 预算是显式保存的版本快照，非实时多人电子表格。画布读屏、Excel 文件兼容尚未专项验收。
- 日历周视图和示例数据围绕 2026 年 11 月发布场景；没有接入外部日历服务。
- 没有 Service Worker，完全关闭后不能保证在无网络时重新加载应用。
